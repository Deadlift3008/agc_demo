# Демо курса

Демо работы с LLM и агентами через [OpenRouter](https://openrouter.ai).
Показывает связку: тонкий фронт → TS-бекенд → шина NATS → питон-рантайм агента → LLM,
со стримингом ответа обратно на фронт в реальном времени.

## Архитектура

```
Frontend (Vite/React)              Backend (TS/Fastify)            Agent (Python)
  POST /api/chat   ── proxy ──►   publish → agent.requests  ──►   слушает NATS
  { messages[], model,                                             + системный промпт
    temperature?,                 subscribe ◄─ agent.resp.<id> ◄─  дёргает OpenRouter
    top_p? }                      пишет SSE на фронт                стримит токены
        ▲                              │
        └──────── стрим токенов ◄──────┘

  GET/POST /api/system-prompt ─►  request → agent.system_prompt.* ─► читает/пишет файл
```

- **frontend** — чат в стиле ChatGPT: лента сообщений, поле ввода снизу, «Новый чат» и
  «Настройки» (модель, температура, top-p, **редактор системного промпта**).
- **backend** — на запрос кладёт всю историю в NATS, подписывается на reply-сабжект и стримит
  токены на фронт (SSE-фрейминг поверх обычного HTTP-ответа); get/set системного промпта
  проксирует в агента через NATS request-reply.
- **agent** — слушает `agent.requests`, подставляет системный промпт перед историей, ходит в
  OpenRouter напрямую (httpx, `stream=true`), парсит SSE и публикует токены обратно в
  `agent.resp.<reqId>`. Системный промпт хранит в файле `agent/system_prompt.txt` рядом с
  рантаймом и читает его на каждый запрос.
- **nats** — шина сообщений (core pub/sub, без JetStream).

Ключ OpenRouter знает только контейнер `agent` — бекенд его не видит.

## Запуск

1. Создай `.env` из примера и впиши ключ:

   ```bash
   cp .env.example .env
   # отредактируй OPENROUTER_API_KEY
   ```

2. Подними всё:

   ```bash
   docker compose up --build
   ```

3. Открой фронт: <http://localhost:5173>

## Порты

| Сервис   | Порт | Назначение            |
|----------|------|-----------------------|
| frontend | 5173 | UI                    |
| backend  | 8080 | HTTP API (/api/chat)  |
| nats     | 4222 | клиентский порт NATS  |
| nats     | 8222 | мониторинг NATS       |

## Настройки в UI

- **Модель** — селектор (дефолт `deepseek/deepseek-v4-flash`).
- **Температура** / **top-p** — если поля пустые, не отправляются (берутся дефолты модели).
- **Системный промпт** — текстовое поле; «Сохранить промпт» пишет его в файл
  `agent/system_prompt.txt` у агента, и он применяется к следующим сообщениям.
- **Новый чат** — очищает историю (агент истории не хранит, она едет с каждым запросом).

## Смотрелка БД (`/db`)

Read-only просмотр Postgres прямо из браузера, без SQL и без редактирования.
Реализована на бекенде (`backend/src/db.ts`), фронт — аккордеон со списком таблиц.

- `GET /api/db/tables` — разрешённые таблицы с числом строк и колонками
  (колонки берутся из `information_schema`).
- `GET /api/db/tables/:name?limit=&offset=` — содержимое таблицы постранично.

Доступ только к таблицам из белого списка `ALLOWED_TABLES` (имя → захардкоженная
сортировка). Имя таблицы и `ORDER BY` никогда не берутся из ввода пользователя, а
`limit`/`offset` идут через параметры запроса — защита от SQL-инъекций. На фронте:
клик по таблице разворачивает её содержимое, пагинация prev/next, счётчик
«1–25 of N», refresh; ячейки рендерятся умно (null → «—», объекты → усечённый
JSON, длинный текст обрезается с тултипом).

## Парсеры GitHub (без ключа)

Кнопка **«⤓ Выкачать с GitHub»** на `/db` дёргает `POST /api/db/sync`. Бекенд
(`backend/src/github.ts`) для КАЖДОГО репозитория из таблицы `repos` ходит в
публичный REST API GitHub **без токена** (лимит — 60 запросов/час на IP) и
выкачивает связанные сущности: метаданные репо (stars/forks/описание…), коммиты,
пул-реквесты, issues и релизы — раскладывая их по таблицам с `INSERT … ON CONFLICT`
(idempotent, без дублей). Глубина — до `MAX_PAGES` страниц по 100 на тип (бережём
лимит). Обязателен только заголовок `User-Agent` (этого требует GitHub).
